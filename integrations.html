整合實戰

把前端、後端（Workers）與資料庫串起來的實作教學——完整 CRUD、認證、檔案上傳、架構藍圖與請求流程圖。

認識每個產品只是第一步，真正的重點是把它們串起來。這些教學示範網頁如何呼叫 Worker、Worker 如何讀寫資料庫，以及怎麼把整套系統組起來——每篇都搭配大量 mermaid 圖解。

全端串接基礎 7

account_tree前端、後端、資料庫是怎麼串起來的用一張大局觀地圖，看懂 Cloudflare 上的全端應用——以及一個請求是怎麼穿過每一層的開始學sync_alt前端 ↔ Worker ↔ D1：完整 CRUD 串接把網頁串到 Worker API，再接上 SQL 資料庫開始學api用 Workers 設計 REST API在單一個 Worker 上打造乾淨的 HTTP 後端：用「方法 + 路徑」做路由、解析請求、回傳帶正確狀態碼的 JSON，並用 CORS 讓瀏覽器前端可以直接呼叫它。開始學dynamic_formHTML 表單 → Worker → 資料庫最經典的流程：送出表單、存起來、再顯示出來——搭配真正的伺服器端驗證開始學lock_person前後端認證串接在 Cloudflare 串接登入的兩種做法：零信任 Access，或自己用 KV 管 session開始學upload_file檔案上傳：前端 → Worker → R2讓使用者從網頁上傳圖片與文件，存進 R2，再提供下載，並把中繼資料（檔案的描述資料）記在 D1。開始學web用 Pages + Functions 部署全端應用用同一個 Cloudflare Pages 專案，同時放前端網頁、跑後端 API開始學

資料庫與儲存 6

alt_route我該用哪種儲存？KV / D1 / R2 / Durable Objects / Hyperdrive 選型一份選型指南：把你資料的「形狀」對應到最適合的 Cloudflare 儲存開始學schema設計 D1 資料庫綱要（資料表與 migration）用 SQLite 設計 users 與 posts 資料表，再用 migration 安全地讓綱要隨時間演進開始學shareD1 的關聯與 JOIN 查詢在 D1 裡建立一對多與多對多資料模型，再用 JOIN 查詢與批次交易把它們串起來開始學bolt用 KV 在資料庫前面加一層快取在 D1 前面擺一層快速的鍵值快取，替「讀多寫少」的資料降低延遲與成本開始學hub用 Durable Objects 管理強一致狀態讓單一 Durable Object 成為計數器、鎖、即時房間的唯一真相來源開始學database用 Hyperdrive 讓 Worker 連既有的 Postgres對你的區域 Postgres 做連線池與查詢快取，讓 Workers 維持飛快開始學
